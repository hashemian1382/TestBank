# تست‌بانک — React frontend

بانک تست فارسی و راست‌به‌چپ با React، TypeScript، Vite و Tailwind. این نسخه همچنان **فرانت‌اند با API محلی** است؛ بک‌اند جدیدی به آن متصل نشده است.

## اجرا

Node.js **22.12 یا جدیدتر** پیشنهاد می‌شود (فایل `.nvmrc` روی شاخه‌ی 22 است).

```bash
npm ci
npm run dev
```

```bash
npm run typecheck  # بررسی TypeScript، شامل تست‌ها
npm test          # تست‌های واحد و یکپارچه‌ی LocalApi
npm run build     # خروجی تولیدی در dist
npm run preview   # نمایش خروجی تولیدی
```

تست مرورگر، با یک dev server در ترمینال جداگانه:

```bash
npx playwright install --with-deps chromium
npm run dev -- --port 5173
# در ترمینال دوم:
npm run test:e2e
```

متغیر `PLAYWRIGHT_BASE_URL` برای تست سرور دیگری قابل تنظیم است. در CI، Playwright خودش سرور موقت تست را راه می‌اندازد. `npm run check` بررسی TypeScript، تست‌های واحد/یکپارچه و build را پشت‌سرهم اجرا می‌کند.

## امکانات افزوده‌شده

### ۱. مدیریت درسنامه‌ها

از منوی مدیریت، **درسنامه‌ها** (`#/admin/lessons`) را باز کنید:

- ساخت، ویرایش، مشاهده، کپی مستقل و حذف با تأیید؛ خروجی JSON از نتایج فیلترشده.
- انتخاب درس و مبحث، عنوان، خلاصه/هدف، برچسب، ترتیب در مبحث و زمان مطالعه‌ی دستی یا خودکار.
- حالت **پیش‌نویس** و **منتشرشده**؛ درسنامه‌های قدیمی منتشرشده باقی می‌مانند.
- نگارش Markdown سبک با ابزار تیتر، زیرتیتر، تأکید، فهرست، مراحل، نکته، جدول، کد، متن چپ‌به‌راست و فرمول LaTeX.
- الگوی آماده‌ی آموزشی، پیش‌نمایش کامل و نگارش/پیش‌نمایش کنار هم با همان رندرر صفحه‌ی مطالعه.
- فهرست مطالب قابل پیمایش، تصویر با آدرس یا فایل محلی، متن جایگزین، زیرنویس و عرض نمایش.
- جستجو در عنوان، خلاصه، برچسب و دسته‌بندی؛ فیلتر درس/مبحث/وضعیت و نمایش مرحله‌ای نتایج.
- هشدار خروج بدون ذخیره از ویرایشگر و هشدار بازخوانی/بستن تب برای تغییرات ذخیره‌نشده.

تصویر را با دکمه‌ی «درج در محتوا» در یک خط جداگانه قرار دهید. HTML دلخواه اجرا نمی‌شود. درسنامه‌ی منتشرشده نمی‌تواند محتوای خالی داشته باشد؛ پیش‌نویس می‌تواند ناقص بماند.

### ۲. اتصال مستقیم درسنامه به سوال

در ساخت یا ویرایش سوال، بخش **درسنامه‌های این سوال** در دسترس است:

- یک یا چند درسنامه‌ی موجود از درس‌های سوال را انتخاب کنید؛ لازم نیست مبحثشان دقیقاً با مبحث سوال یکی باشد.
- با «ساخت درسنامه برای سوال» درسنامه‌ی تازه بنویسید. **سوال و همه‌ی درسنامه‌های جدید همراه آن در یک تراکنش ذخیره می‌شوند.** انصراف یا خطای ذخیره، درسنامه‌ی یتیم ایجاد نمی‌کند.
- قطع اتصال، خود درسنامه را حذف نمی‌کند. حذف درسنامه از مدیریت، اتصال آن را از تمام سوال‌ها پاک می‌کند، نه خود سوال‌ها را.
- در کارت سوال، همه‌ی درسنامه‌های مستقیم و پیشنهادهای مبحث، بدون تکرار، قابل انتخاب‌اند. اتصال مستقیم اول نمایش داده می‌شود.
- پیش‌نویس برای کاربر عادی نمایش داده نمی‌شود؛ قواعد خرید درس برای مطالعه پابرجاست.

### ۳. ورود گروهی با ساخت خودکار مبحث

از **ورود گروهی** (`#/admin/import`) استفاده کنید. نمونه‌های قابل اجرا در `examples/bulk-questions.json` هستند.

```json
[
  {
    "subjects": ["cs-os"],
    "topics": ["مبحث جدید زمان‌بندی"],
    "stem": "در RR با کوانتوم بسیار بزرگ، رفتار زمان‌بند به کدام روش نزدیک است؟",
    "options": ["FCFS", "SJF", "Priority", "Multilevel Queue"],
    "correct": 1,
    "explanation": "هر فرآیند تا پایان اجرا می‌شود؛ رفتار شبیه FCFS است.",
    "difficulty": 1
  }
]
```

- نام مبحثِ ناموجود خودکار در درس مربوط ساخته می‌شود؛ همان مبحث در ردیف‌های بعد دوباره استفاده می‌شود.
- ی/ک عربی، فاصله‌ی اضافی و نیم‌فاصله در مقایسه‌ی نام‌ها یکسان‌سازی می‌شوند.
- **در سوال چنددرسی، عنوان ساده‌ی مبحث به همه‌ی درس‌های `subjects` اعمال می‌شود.** برای محدودکردن به یک درس از شناسه‌ی مبحث یا شیء زیر استفاده کنید:

```json
{
  "subjects": ["cs-os", "cs-dsa"],
  "topics": [
    { "subject": "cs-os", "title": "زمان‌بندی پیشرفته" },
    "cs-dsa-t1"
  ],
  "stem": "صورت سوال مشترک",
  "options": ["الف", "ب", "ج", "د"],
  "correct": 1
}
```

- درس باید از قبل موجود باشد. شناسه‌ی مبحثِ متعلق به درس دیگر خطای واقعی است، نه نام مبحث جدید.
- هر ردیف **پیش از ثبت سوال و مباحث جدید آن** کامل اعتبارسنجی می‌شود؛ ردیف خراب مبحث اضافی باقی نمی‌گذارد.
- ردیف‌های سالم وارد می‌شوند؛ تعداد، نام مباحث ساخته‌شده و خطای شماره‌دار هر ردیف گزارش می‌شود. «اصلاح فقط ردیف‌های ناموفق» از ورود دوباره‌ی ردیف‌های موفق جلوگیری می‌کند.
- یک ورودی پس از ثبت دوباره ارسال نمی‌شود، مگر متن را ویرایش یا فایل تازه بارگذاری کنید. این محافظ UI است، نه تشخیص سوال‌های تکراری در فایل‌های متفاوت.
- `correct` به‌طور پیش‌فرض **۱ تا ۴** است. برای ۰ تا ۳، `correctBase: 0` را صریح بنویسید. صفر بدون `correctBase` فقط برای سازگاری با نسخه‌ی قدیمی به معنی گزینه‌ی اول پذیرفته می‌شود.
- `lessonIds` برای درسنامه‌های موجود و `isActive` برای وضعیت سوال پشتیبانی می‌شوند. اگر `source` حذف شود منبع تألیفی استفاده می‌شود؛ منبعِ صریح ولی ناموجود گزارش خطا می‌دهد.
- برای عنوان‌های واقعاً تکراری و مبهم، شناسه بدهید یا ابتدا ادغام کنید؛ مبحث به‌صورت تصادفی انتخاب نمی‌شود.

### ۴. تغییر نام و ادغام مباحث

در **درس‌ها و مباحث** (`#/admin/catalog`) روی «مباحث» یک درس بزنید:

1. برای تغییر نام، دکمه‌ی ویرایش کنار مبحث را بزنید و «ذخیره نام مبحث» را انتخاب کنید.
2. برای ادغام، دست‌کم دو مبحث از **همان درس** را انتخاب کنید.
3. نام نهایی را وارد کنید؛ نام تازه یا نام یکی از انتخاب‌ها قابل استفاده است. اگر نام مقصد مربوط به مبحث دیگری است آن را هم انتخاب کنید.
4. «بررسی اثر ادغام» تعداد سوال‌ها، درسنامه‌ها، قالب‌ها و اجراهای آزمونِ تحت تأثیر را در داده‌های همه‌ی کاربران نشان می‌دهد.
5. پس از بررسی، تأیید صریح را علامت بزنید و ادغام کنید.

**اثر داده‌ای:**

- تغییر نام شناسه را حفظ می‌کند؛ همه‌ی نماهای مبتنی بر مبحث نام تازه را نشان می‌دهند.
- ادغام یکی از شناسه‌های انتخابی را نگه می‌دارد؛ `question.topicIds`، `lesson.topicId` و `blueprint.topicIds` در تمام داده‌ها بازنویسی و تکرارها حذف می‌شوند.
- آمار `result.byTopic` آزمون‌های پایان‌یافته از سوال‌ها/تصویر تاریخی آن‌ها بازطبقه‌بندی می‌شود، نه با جمع ساده‌ی آمار قبلی؛ سوال چندمبحثی دوبار شمرده نمی‌شود.
- نمره‌ی کل، پاسخ‌ها، ترتیب سوال‌های آزمون، زمان‌ها، آمار درس، مجموعه‌ها، نشان‌ها، محتوا و شناسه‌ی درسنامه‌ها تغییر نمی‌کنند.
- نام‌ها و شناسه‌های قدیمی به‌عنوان alias نگه داشته می‌شوند تا ورود فایل قدیمی یا لینک فیلتر قدیمی دوباره مبحث جدا نسازد.
- ترتیب مباحث در یک عملیات ذخیره می‌شود. حذف مبحثِ دارای سوال، درسنامه یا سابقه‌ی آزمون مسدود است تا ارجاع شکسته ایجاد نشود.

ادغام برگشت خودکار ندارد. این عملیات دسته‌بندی را تغییر می‌دهد؛ داخل متن آزاد سوال‌ها و درسنامه‌ها جستجو/جایگزینی لفظی انجام نمی‌دهد.

## ماندگاری و سازگاری

- داده‌ها همچنان در localStorage همین **مرورگر و origin** ذخیره می‌شوند؛ دستگاه یا دامنه‌ی دیگر داده‌ی مستقلی دارد.
- کلیدهای `testbank.db.v2` و `testbank.session.v2` عوض نشده‌اند. نسخه‌ی داخلی پایگاه از ۲ به ۳ ارتقا می‌یابد؛ داده‌های کاربران، خریدها، تنظیمات، سوال‌ها و درسنامه‌های قبلی با seed جایگزین نمی‌شوند.
- هر تغییر ابتدا روی یک نسخه‌ی مستقل اعمال و سپس ذخیره می‌شود. اگر سهمیه پر یا دسترسی مسدود باشد، خطا نمایش داده می‌شود و نسخه‌ی قبلی در حافظه و دیسک باقی می‌ماند.
- داده‌ی خراب یا نسخه‌ی ناشناخته بی‌صدا پاک نمی‌شود؛ خطای قابل مشاهده نمایش داده می‌شود.
- تغییرات تب دیگر هنگام خواندن تازه دریافت و از طریق رویداد storage به نماها اعلام می‌شوند. این جایگزین تراکنش چندکاربره‌ی سرور نیست.
- سقف تصویر بارگذاری‌شده‌ی محلی ۱ MiB است؛ کل ظرفیت localStorage به مرورگر بستگی دارد. برای تصاویر حجیم URL رسانه استفاده کنید. CSS فرمول‌ها و فونت فارسی محلی بسته‌بندی می‌شوند و به CDN وابسته نیستند.

### نکته‌ی سوابق قدیمی

نسخه‌ی قبلی پاسخ صحیح تاریخی و دسته‌بندی هر سوال در زمان اتمام آزمون را ذخیره نمی‌کرد. برای سوابق قدیمی، snapshot از سوال‌های موجود ساخته می‌شود و بازسازی مبحثی بر همان مبناست؛ نمره‌ی کل قبلی دست‌نخورده می‌ماند. اگر سوال یک سابقه‌ی قدیمی قبلاً حذف شده و جزئیات لازم موجود نباشد، ادغام به‌جای حدس‌زدن آمار متوقف می‌شود و نام آن سابقه را گزارش می‌کند. آزمون‌های جدید snapshot سبک دارند و حذف/ویرایش بعدی سوال پاسخ صحیح تاریخی آن‌ها را در این بازطبقه‌بندی عوض نمی‌کند.

یکی از سوال‌های seed قبلی (`q-ai-003`) از قبل مبحث پیش‌نیازِ درس دیگری را داشت. ویرایش محتوایی/اتصال درسنامه این ارجاع و مالکیت قبلی را حفظ می‌کند و فرم هشدار توضیحی دارد. در **نسخه‌ی کپی یا خروجی قابل ورود مجدد** درسِ مباحث میان‌درسی هم درج می‌شود تا ردیف جدید معتبر باشد؛ اصل سوال دست‌کاری نمی‌شود.

## ساختار تغییرات و اتصال آینده به بک‌اند

- `src/pages/admin/AdminLessons.tsx`, `LessonEditor.tsx`: مدیریت و نگارش درسنامه.
- `src/pages/admin/QuestionLessons.tsx`: انتخاب درسنامه و صف درسنامه‌های جدید سوال.
- `src/pages/admin/TopicsPanel.tsx`: مدیریت و پیش‌نمایش ادغام.
- `src/services/contentValidation.ts`: اعتبارسنجی مشترک.
- `src/services/bulkImport.ts`: ورود گروهی و ساخت مباحث با scope روشن.
- `src/services/topicOperations.ts`: منطق بازطبقه‌بندی و حفظ ارجاع‌ها.
- `src/services/localApi.ts`: مهاجرت، ذخیره‌سازی تراکنشی و پیاده‌سازی قرارداد سرویس.
- `src/lib/richText.ts`, `src/components/LessonContent.tsx`: رندر یکسان پیش‌نمایش و مطالعه.

راهنمای قرارداد و endpointهای پیشنهادی: [src/services/README.md](src/services/README.md). گزارش آزمون‌ها: [docs/verification.md](docs/verification.md).

**برای انتشار واقعی**، احراز هویت، مجوز مدیریت، مالکیت محتوای خریداری‌شده، ذخیره‌ی فایل و تراکنش‌های ادغام/ورود گروهی باید در بک‌اند enforce شوند؛ LocalApi محیط توسعه است.
